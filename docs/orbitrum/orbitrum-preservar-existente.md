# NÃO REMOVER O QUE EXISTE — SÓ ADICIONAR O QUE FALTA

**Erro que cometi (2× no mesmo dia, 29/09/2026):** troquei/removi o **sistema orbit**
(profissionais orbitando o miolo, componente `orbit-system.tsx`) por outra coisa (um "Neural
Core" de nós de categoria). O Pedro **nunca** pediu para tirar. Pediu só ADICIONAR o que
faltava (Empresas/Oportunidades). Cobrança dele: *"não deve sumir o sistem orbit que orbitam,
falei para entrar só o que faltava, não mudar o sistema ali... isso 2 vez hoje"* e *"vejo sair
do que peço"*.

**Why:** o Pedro tem uma visão clara e um design-alvo. Quando eu troco algo que ele curte, é
regressão e quebra confiança — pior que design feio é remover o que ele pediu para manter. Ele
paga por tokens e não quer gastar refazendo o que eu quebrei.

**How to apply (regra dura, sempre):**
1. **Só adição.** Se o pedido é "falta X", eu ADICIONO X **ao lado** do que existe. Nunca
   substituo/removo um componente existente para encaixar o novo. Em especial: **o sistema orbit
   (`orbit-system.tsx`, profissionais orbitando + busca) fica intacto no miolo da home.**
2. **Antes de qualquer mudança estrutural** (trocar componente central, mudar rota da home,
   remover algo visível), eu **paro e confirmo** com o Pedro — não presumo.
3. **Ler o pedido literal.** "entrar só o que faltava" = adicionar só o que falta, não redesenhar.
4. **Não sair do escopo.** Escopo = só Orbitrum, e dentro dele só o que o Pedro pediu naquele
   momento. Sem redesenhar por conta própria.
5. **Empírico + memória + diário sempre** ([[orbitrum-modo-de-trabalho]], [[orbitrum-checklist]]):
   testar de verdade, e registrar erro como este para não repetir.

Ligado a [[orbitrum-visao]] (não-regressão é princípio nº1) e [[orbitrum-design-alvo]]
(o design é o norte, mas se constrói SOBRE o que já existe, não apagando).
